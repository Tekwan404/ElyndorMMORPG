Elyndor — Attributes and Stats System Specification

Document: docs/source-of-truth/gameplay/06_ATTRIBUTES_AND_STATS_SYSTEM.md
System: Attributes / Stats
Status: Foundation / Source of Truth
Version: 0.2

1. Назначение

Attributes and Stats System определяет утверждённый набор характеристик персонажей, NPC, монстров и других игровых сущностей.

Система задаёт:

базовые атрибуты;
атакующие характеристики;
защитные характеристики;
модификаторы характеристик;
правила применения модификаторов;
правила snapshot'ов;
взаимодействие характеристик с Combat System и другими системами.

Attributes and Stats System не определяет:

конкретный числовой баланс;
точные формулы урона;
точные формулы лечения;
точные формулы критического удара;
точные формулы брони и сопротивлений;
лут-таблицы;
экономику;
AI;
UI;
классовую систему в деталях.

2. Основной принцип

Все характеристики являются серверными данными.

Клиент может отображать характеристики, но не является источником истины.

Сервер определяет:

базовые значения;
модификаторы;
итоговые значения;
момент применения изменений;
snapshot'ы для действий.

В текущей версии системы используется только утверждённый ниже набор характеристик.

Другие характеристики не вводятся, если это отдельно не согласовано.

3. Утверждённый набор характеристик

Характеристики делятся на три категории:

Основные характеристики.
Атакующие характеристики.
Защитные характеристики.

4. Основные характеристики

Основные характеристики являются базовыми атрибутами персонажа.

Они могут влиять на производные боевые параметры, но конкретные формулы влияния будут определены позднее.

Strength / Сила

Основной физический атрибут для силовых классов.

Может использоваться для:

физических билдов;
физических способностей;
требований к экипировке;
производных физических характеристик.

Agility / Ловкость

Основной физический атрибут для ловких классов.

Может использоваться для:

ловких билдов;
физических способностей;
требований к экипировке;
производных физических характеристик.

Intellect / Интеллект

Основной магический атрибут.

Может использоваться для:

магических билдов;
магических способностей;
лечения;
требований к магической экипировке;
производных магических характеристик.

Stamina / Выносливость

Увеличивает максимальный запас здоровья.

Основное назначение:

определять или участвовать в определении MaxHP;
повышать выживаемость персонажа.

Spirit / Дух

Spirit не входит в активный набор характеристик Elyndor. Идентификатор зарезервирован только для возможного будущего расширения и не используется формулами, экипировкой, классами или ресурсами.


5. Атакующие характеристики

Атакующие характеристики определяют наступательную эффективность персонажа.

AttackPower / Сила атаки

Усиливает физические атаки и физические способности.

Используется для:

автоатак физического типа;
физических способностей;
физических эффектов, если это определено способностью.

SpellPower / Сила заклинаний

Усиливает магические способности и лечение.

Используется для:

магических способностей;
лечащих способностей;
магических эффектов, если это определено способностью.

CriticalChance / Шанс критического удара

Вероятность нанести критический удар.

Проверка критического удара выполняется сервером.

Клиент не определяет результат броска.

CriticalDamage / Критический урон

Хранится как **дополнительная доля урона критического удара сверх обычного попадания**.

Базовое значение:

```text
CriticalDamage = 100%
CriticalDamageMultiplier = 1 + CriticalDamage = 2.0
```

То есть базовый крит наносит 200% обычного урона.

Талант `+15% CriticalDamage` увеличивает значение до 115%, а итоговый multiplier становится 2.15.

UI может отображать либо `Critical Damage Bonus = 100%`, либо `Critical Damage Total = 200%`, но transport/domain contracts используют одну утверждённую bonus-модель.

Accuracy / Меткость

Уменьшает вероятность промаха.

Используется при разрешении атак и способностей, если система допускает промахи.

Конкретная формула взаимодействия Accuracy и Dodge определяется отдельно.

ArmorPenetration / Пробивание брони

Уменьшает эффективность физической брони цели.

Используется при расчёте физического урона.

MagicPenetration / Пробивание магии

Уменьшает эффективность магического сопротивления цели.

Используется при расчёте магического урона.

AttackSpeed / Скорость атаки

Уменьшает интервал между автоатаками относительно базовой скорости оружия.

AttackSpeed не является самостоятельным оружием.

Он модифицирует Weapon Base Attack Interval.

Базовая модель:

Weapon Base Attack Interval
  ↓
Attack Speed modifiers
  ↓
Final Attack Interval

Конкретная формула финального интервала будет определена позднее.

6. Защитные характеристики

Защитные характеристики определяют способность персонажа уменьшать или избегать входящий урон.

Armor / Броня

Уменьшает входящий физический урон.

Используется при расчёте физического урона.

MagicResistance / Магическое сопротивление

Уменьшает входящий магический урон.

Используется при расчёте магического урона.

Dodge / Уклонение

Шанс полностью избежать подходящей атаки.

Проверка уклонения выполняется сервером.

Клиент не определяет результат броска.

7. Служебные параметры здоровья и ресурса

Для работы боя и способностей необходимы служебные параметры состояния.

Они не являются основными, атакующими или защитными характеристиками из утверждённого списка, но существуют как системные значения.

MaxHP

Максимальный запас здоровья персонажа.

MaxHP увеличивается за счёт Stamina и может дополнительно изменяться другими источниками, если это разрешено системой.

CurrentHP

Текущее здоровье персонажа.

Если CurrentHP достигает 0, персонаж переходит в состояние DEAD.

MaxResource

Максимальный запас ресурса, если персонаж использует ресурс.

Тип ресурса может зависеть от класса, билда или архетипа.

CurrentResource

Текущее количество ресурса.

Если CurrentResource недостаточно, способность не может быть использована, если иное не определено правилом способности.

8. Источники характеристик

Характеристики могут происходить из нескольких источников.

Base Character Source

Базовые атрибуты персонажа.

Level Source

Изменения от уровня персонажа.

Equipment Source

Экипировка:

оружие;
броня;
аксессуары;
другие слоты, если будут добавлены.

Talent Source

Таланты, пассивные деревья, специализации, если будут добавлены.

Buff Source

Положительные эффекты.

Debuff Source

Отрицательные эффекты.

Consumable Source

Временные предметы, если будут добавлены.

World Source

Эффекты мира, территории, погодные условия, мировые события, если будут добавлены.

Instance Source

Правила инстанса.

Scripted Source

Скриптовые события и временные сценарии.

9. Modifier Types

Модификаторы должны иметь тип и правило применения.

Flat Modifier

Добавляет или вычитает фиксированное значение.

Пример:

+10 Strength
+100 AttackPower
-50 Armor

Percent Modifier

Изменяет значение на процент.

Пример:

+10% Attack Speed
+15% Critical Damage
-20% Armor

Multiplicative Modifier

Отдельный множитель, если это требуется для особых эффектов.

Пример:

Damage dealt x1.5
Damage taken x0.8

Conditional Modifier

Применяется только при выполнении условия.

Примеры:

+20% Critical Chance against beasts;
+10% Dodge while below 30% HP;
+15% Spell Power during night, если будет добавлено.

Conditional modifiers должны быть явно проверены сервером.

10. Порядок применения модификаторов

Для предсказуемости рекомендуется базовый порядок:

BaseValue
  ↓
+ Flat Modifiers
  ↓
+ Percent Modifiers
  ↓
× Multiplicative Modifiers
  ↓
Clamp Min/Max
  ↓
FinalValue

Конкретная формула может отличаться для отдельных характеристик, если это явно определено системой.

11. Минимальные и максимальные ограничения

Характеристики должны иметь допустимые границы.

Базовые правила:

CriticalChance min = 0%
CriticalChance max = 100%
Dodge min = 0%
Dodge max = 100%
CurrentHP min = 0
CurrentResource min = 0

Другие caps будут определены позднее.

12. Stat Calculation Pipeline

Вычисление характеристик должно быть контролируемым и воспроизводимым.

Базовый pipeline:

Base Attributes
  ↓
Level Growth
  ↓
Equipment Bonuses
  ↓
Talent Bonuses
  ↓
Active Effects
  ↓
Conditional Checks
  ↓
Final Stats
  ↓
Stat Cache / Snapshot

Если источник изменения теряет актуальность, характеристики должны быть пересчитаны.

Примеры причин пересчёта:

level up;
equipment changed;
buff expired;
debuff applied;
talent changed;
zone rule changed;
balance patch changed formula.

13. Stat Cache

Для производительности система может кэшировать итоговые характеристики.

Однако кэш должен быть инвалидирован при изменении источников.

Кэш не должен использоваться, если:

характеристики были изменены;
эффект истёк;
персонаж перешёл в другое состояние;
сервер восстанавливает состояние после restart;
требуется snapshot действия.

14. Snapshot характеристик

Snapshot — это зафиксированный набор характеристик на определённый момент времени.

Snapshot нужен для:

casted abilities;
instant abilities;
combat resolution;
audit and debugging;
combat replays, если будут добавлены.

15. Snapshot Timing

Для casted ability snapshot по умолчанию фиксируется в момент успешного начала каста.

Пример:

12:00:00 — Spell Power = 500
12:00:00 — Fireball cast starts
12:00:01 — Spell Power becomes 700
12:00:02 — Fireball resolves

Fireball использует snapshot от 500 Spell Power.

Instant Ability использует snapshot в момент использования.

Next Attack Modifier не обязан snapshot'ить будущую атаку.

Сама атака разрешается по правилам Combat System в момент её выполнения.

16. Stat Changes and Future Actions

Изменение характеристики не должно ретроактивно менять уже разрешённые действия.

Пример:

Если урон уже нанесён, последующее изменение AttackPower не должно пересчитывать уже нанесённый урон.

Если каст уже завершён, последующее изменение SpellPower не должно менять завершённый каст.

Если атака уже разрешена, последующее изменение AttackSpeed не должно менять её задним числом.

Изменения влияют на будущие действия.

17. Attack Speed Changes

Attack Speed влияет на будущие циклы Auto Attack.

Базовое правило:

Изменение Attack Speed не пересчитывает уже разрешённую атаку.

Точная политика изменения уже запланированной, но ещё не разрешённой атаки будет определена Combat System.

18. Interaction with Combat System

Combat System использует утверждённые характеристики для разрешения боя.

Примеры использования:

AttackPower — физические атаки и физические способности.
SpellPower — магические способности и лечение.
CriticalChance — проверка критического удара.
CriticalDamage — расчёт критического урона.
Accuracy — проверка промаха.
Dodge — проверка уклонения.
Armor — уменьшение физического урона.
MagicResistance — уменьшение магического урона.
ArmorPenetration — игнорирование части физической брони.
MagicPenetration — игнорирование части магического сопротивления.
AttackSpeed — интервал между автоатаками.

Конкретные формулы боя определяются Combat System.

19. Interaction with AFK Farming

AFK Farming не вводит новые характеристики.

AFK Farming может использовать только утверждённый набор характеристик и производный профиль эффективности, если это требуется для расчёта бонуса.

AFK Farming по умолчанию:

не расходует ресурсы;
не ломает экипировку;
не приводит к смерти;
не использует полноценный боевой simulation.

Если AFK System использует эффективность персонажа, она должна опираться на:

уровень;
экипировку;
билд;
утверждённые характеристики;
локацию;
контекст противников.

20. Interaction with World System

World System может предоставлять контекст, влияющий на характеристики.

Примеры:

zone buff;
world event;
territory modifier;
instance modifier.

Однако World System не должна напрямую хранить финальные характеристики персонажа.

Она предоставляет контекст, а Attributes and Stats System применяет модификаторы.

21. Quest Integration

Attributes and Stats System может предоставлять Quest System факты о характеристиках.

Примеры:

CharacterReachedLevel
AttributeChanged
StatThresholdReached

По умолчанию система не должна отправлять каждое изменение каждой характеристики в Quest System.

Quest System должен получать только релевантные события.

22. Events

Attributes and Stats System может эмитить события об изменениях.

Примеры:

StatsRecalculated
AttributeChanged
StatModifierApplied
StatModifierRemoved
HealthDepleted
ResourceDepleted

События должны быть серверно-авторитетными.

23. Persistence

Характеристики персонажа должны быть сохраняемыми или восстанавливаемыми.

Для персонажа сохраняются:

base attributes;
level;
equipment state;
current HP;
current resource;
active persistent modifiers;
stat version;
last recalculated timestamp.

Временные эффекты могут быть сохраняемыми или временными в зависимости от Effects System.

24. Restart Recovery

После server restart характеристики должны быть восстановлены.

Базовые правила:

expired effects не должны применяться;
active timed effects проверяются по Server Time;
final stats пересчитываются при необходимости;
CurrentHP не должен быть отрицательным;
CurrentResource не должен быть отрицательным;
death state обрабатывается Character System.

25. Stat Invariants

INVARIANT-01
Сервер является источником истины для характеристик.

INVARIANT-02
Клиент не может напрямую изменять финальные характеристики.

INVARIANT-03
Используется только утверждённый набор характеристик.

INVARIANT-04
Final Stat вычисляется из Base Value и активных модификаторов.

INVARIANT-05
Изменение характеристики не должно ретроактивно менять уже разрешённые действия.

INVARIANT-06
Casted Ability по умолчанию использует snapshot характеристик в момент начала каста.

INVARIANT-07
Instant Ability использует snapshot в момент использования.

INVARIANT-08
Next Attack Modifier не обязан snapshot'ить будущую атаку.

INVARIANT-09
CurrentHP = 0 переводит персонажа в состояние DEAD.

INVARIANT-10
CurrentResource не может быть меньше нуля.

INVARIANT-11
CriticalChance и Dodge проверяются сервером.

INVARIANT-12
AttackSpeed модифицирует интервал автоатак относительно базовой скорости оружия.

INVARIANT-13
ArmorPenetration уменьшает эффективность физической брони цели.

INVARIANT-14
MagicPenetration уменьшает эффективность магического сопротивления цели.

INVARIANT-15
Spirit не является активной характеристикой и не используется игровыми формулами.

INVARIANT-16
Характеристики NPC/монстров могут использовать ту же модель, но конкретные профили определяются отдельно.

INVARIANT-17
Attributes and Stats System не хранит квестовый прогресс.

Следующие параметры не являются частью текущей системы и не должны использоваться, если не будут отдельно добавлены:

Movement Speed;
Cast Speed;

Block;
Tenacity;

Luck;

# Source of Truth Revision v2

- Активные Primary: Strength, Agility, Intellect, Stamina.
- Активные Offensive: AttackPower, SpellPower, CriticalChance, CriticalDamage, Accuracy, ArmorPenetration, MagicPenetration, AttackSpeed.
- Активные Defensive: Armor, MagicResistance, Dodge.
- Healing использует SpellPower; отдельный HealingPower не вводится.
- Неактивные/зарезервированные: Spirit, CastSpeed, Parry, Block, MovementSpeed.
- Resource regeneration/max values являются Resource modifiers, а не новыми Stats.
