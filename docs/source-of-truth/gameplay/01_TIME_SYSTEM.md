Elyndor — Time System Specification

Document: docs/source-of-truth/gameplay/01_TIME_SYSTEM.md
System: Time
Status: Foundation / Source of Truth
Version: 0.2

1. Назначение системы

Time System определяет фундаментальные правила времени в Elyndor.

Время является глобальной системой игры и используется всеми подсистемами, которым необходимо определять последовательность, длительность или момент наступления игровых событий.

Time System не отвечает за конкретную игровую механику и не должна знать, что такое атака, способность, моб, квест, гильдия, крафт или AFK-фарм.

Она предоставляет другим системам единый источник времени и механизмы работы с временными событиями.

2. Основной принцип

Elyndor является игрой с непрерывно идущим серверным временем.

Серверное время не останавливается из-за:

выхода игрока;
потери соединения;
отсутствия игроков в локации;
закрытия клиента;
перезапуска клиента.

Игрок может прекратить взаимодействие с игрой, но игровой мир продолжает существовать.

3. Абсолютное время

Сервер использует единое абсолютное время.

Время не зависит от часового пояса конкретного игрока.

Технической основой является UTC.

Часовой пояс игрока используется только для отображения времени на клиенте.

4. Соотношение реального и игрового времени

На базовом уровне Elyndor использует соотношение:

1 реальная секунда = 1 игровая секунда

Если способность имеет Cast Time = 2 секунды, её базовое время каста составляет две реальные секунды.

Если событие должно произойти через 10 минут, оно происходит через десять реальных минут.

5. Server Time — источник истины

Клиент не определяет игровое время.

Сервер самостоятельно определяет:

текущее время;
момент начала действия;
момент завершения действия;
момент наступления события;
cooldown;
duration;
respawn;
resource regeneration;
другие временные процессы.

Клиент сообщает намерение, но не может сообщить серверу, сколько времени якобы прошло.

6. World Time и Simulation Tick

Необходимо различать:

World Time
Абсолютное игровое время.

Simulation Tick
Технический шаг, на котором сервер проверяет и обрабатывает изменения состояния.

Simulation Tick не определяет игровое время и не является игровым правилом.

Конкретный Tick Rate определяется технической архитектурой и нагрузочными тестами и пока не фиксируется.

7. Timers

Долгоживущие таймеры должны концептуально храниться через абсолютную точку завершения.

Пример:

CooldownEndsAt = 12:00:05

Вместо постоянного уменьшения:

5 → 4 → 3 → 2 → 1 → 0

состояние определяется сравнением текущего Server Time с моментом окончания.

Это позволяет корректно работать с:

offline progression;
server restart;
lag;
восстановлением состояния;
большими временными интервалами.

8. Scheduled Events

Системы могут создавать события, которые должны произойти в определённый момент.

Примеры:

World Boss;
начало или окончание мирового события;
открытие NPC-магазина;
респавн моба;
появление ресурса;
завершение производства;
завершение исследования;
квестовый таймер;
событие гильдии.

Пример:

EventStartAt = 2026-08-14T18:00:00Z

9. Persistence и server restart

Состояния, зависящие от времени, должны корректно восстанавливаться после перезапуска сервера.

Система не должна считать, что время остановилось вместе с серверным процессом.

Например, если cooldown должен был завершиться во время перезапуска, после запуска он уже считается завершённым.

Это правило применяется к:

cooldown;
buffs;
debuffs;
crafting;
production;
research;
quests;
respawn;
scheduled events;
другим временным состояниям.

10. Offline Progression

Offline Progression означает, что определённые процессы продолжаются во время отсутствия игрока.

Это не означает полноценную симуляцию всего мира.

Каждая система самостоятельно определяет, какие процессы могут продолжаться offline.

Time System лишь предоставляет временную основу.

11. Character Presence

Пребывание персонажа в мире не должно смешиваться с наличием игрока online.

Игрок может быть offline, при этом персонаж может:

находиться в городе;
находиться в обычной локации;
находиться в опасной локации;
находиться в другом состоянии мира;
участвовать в разрешённых offline-процессах.

Сам факт выхода игрока не удаляет персонажа из игрового состояния и не телепортирует его автоматически в безопасное место.

Конкретные последствия определяются World, Combat и AFK Farming системами.

12. Day / Night Cycle

Elyndor поддерживает игровой цикл дня и ночи.

Игровое время суток может использоваться другими системами.

Например:

определённые монстры появляются только ночью;
другие — только днём;
ресурсы доступны в определённое время;
NPC имеют расписание;
мировые события происходят в определённые периоды;
некоторые задания доступны только в определённое время.

Продолжительность игрового дня и ночи пока не фиксируется.

13. Combat Time

Combat System использует Time System для определения:

Auto Attack timing;
Cast Time;
Cooldown;
Buff duration;
Debuff duration;
DoT ticks;
HoT ticks;
Respawn;
других временных боевых процессов.

Time System не знает правил боя.

14. Action Timing

Игровое действие получает своё серверное время в момент, когда сервер принимает и валидирует это действие.

Пример:

Server receives action: 12:00:00.250
Cast Time: 1.5 sec
Cast Ends At: 12:00:01.750

Клиент не может задать собственный момент начала действия.

15. Snapshot Timing

Для способностей с Cast Time основные параметры действия фиксируются в момент успешного начала каста, если конкретная способность явно не определяет другое правило.

Пример:

12:00:00 — Spell Power = 500, Fireball starts
12:00:01 — player receives +200 Spell Power
12:00:02 — Fireball resolves

Fireball использует snapshot состояния на момент начала каста и считается от 500 Spell Power.

Следующее действие уже использует новое состояние.

Для instant-способности момент использования одновременно является моментом snapshot.

Next Attack Modifier не обязан фиксировать параметры будущей атаки: он создаёт эффект, а сама атака разрешается по правилам Combat System в момент её выполнения.

DoT/HoT snapshot rules будут определены отдельно в Effects System.

16. Time Invariants

INVARIANT-01
Server Time не останавливается из-за offline игрока.

INVARIANT-02
Server Time не зависит от часового пояса игрока.

INVARIANT-03
Клиент не может определять Server Time.

INVARIANT-04
1 реальная секунда соответствует 1 игровой секунде.

INVARIANT-05
Временные процессы должны корректно восстанавливаться после server restart.

INVARIANT-06
Долгоживущие таймеры должны быть представлены через временные точки, а не зависеть от количества обработанных ticks.

INVARIANT-07
Simulation Tick является техническим механизмом и не определяет игровое время.

INVARIANT-08
Time System не содержит бизнес-логику других игровых систем.

INVARIANT-09
Любая система, использующая время, использует единый источник Server Time.

INVARIANT-10
Для casted ability snapshot по умолчанию фиксируется в момент успешного начала каста.

17. Quest System Integration

Quest System может использовать Time System как источник временных условий и ограничений.

Примеры:

начало или окончание временного квеста;
доступность задания только в определённый период;
ожидание до наступления нужного времени суток;
завершение или провал задания по таймеру.

Time System не должна хранить прогресс квеста и не должна определять, выполнено ли задание.

Она только предоставляет авторитетное Server Time и временные события, а Quest System самостоятельно применяет их к правилам конкретного задания.

18. Out of Scope

Этот документ не определяет:

Combat System;
AFK Farming;
AI;
Loot;
Character progression;
Guilds;
Economy;
конкретный Tick Rate;
конкретную базу данных;
клиентскую визуализацию;
конкретные формулы урона;
конкретные правила DoT/HoT snapshot.

19. Основной принцип

Elyndor — постоянный мир.

Игрок может перестать взаимодействовать с игрой, но время мира продолжает идти.

Time System предоставляет единый авторитетный временной контекст для всего игрового мира, но не содержит правила конкретных игровых механик.
