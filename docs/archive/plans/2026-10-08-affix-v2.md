# Affix V2 implementation plan

One PR covers all six requested stages. Base: main da85ac5b.

1. Export every composed ItemDefinition, acquisition references, classes, budget and actual generation envelopes. Record baseline contradictions and combat stat consumers (including healing and companions).
2. Add shared content-authored class/slot eligibility, weighted pools by role and exclusive groups. Reuse the same candidate selection for drop and reforge; validate sufficient capacity for every reachable combination.
3. Publish generation version 2 on rolled templates, retaining IDs, structural stats, art, set membership and affix counts. Update ordinary gear first, progression sets next, branch sets next, Unique pools only for demonstrated contradictions. Holy gets a healing pool; caster pools exclude autoattack-only haste.
4. Export deterministic equal-budget damage/healing/defense comparisons at 10/20/30/40/60, including cap-adjacent cases. Keep budget weights unless measurements justify a change; document limits of isolated-stat comparisons.
5. Reforge uses current eligibility with the persisted slot power envelope. Existing economic transactions and idempotency stay authoritative. The owner permits a beta database reset: do not add legacy stat-cost tables or a special V1 migration layer. No schema migration or database wipe is needed for this implementation.
6. Test eligibility, weighted selection, combination exhaustion, complete composed catalog, old-instance preservation and reforge. Run backend build/tests, content validation, frontend checks; obtain review and merge only with green CI.

Failure cases: malformed/unknown rules; forbidden guarantees; too few candidates after exclusions; shield-only stats on non-shields; legacy affixes that current policy excludes; empty reforge pool; capped stats with zero marginal benefit. No new dependencies or database schema required.

Scope update: consolidate the latest item definitions into canonical source files,
remove superseded hotfix JSON, remove sorting prefixes and enforce one item ID per
authored definition. Verify effective item equality across consolidation.
